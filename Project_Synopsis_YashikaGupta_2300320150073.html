1. Problem Statement (5W1H Framework)

University administration and support desks face massive enquiry surges during admission cycles, semester fee deadlines, and examinations. Over 70% of these queries are repetitive (e.g., fee amounts, hostel refund rules, HOD contacts, and syllabus downloads), resulting in prolonged wait times of 24 to 72 hours, severe administrative staff fatigue, and student anxiety. Human helpdesks operate only during standard office hours (9:00 AM – 5:00 PM), leaving evening and weekend inquiries completely unattended. This project resolves the problem by engineering an intelligent, self-contained AI chatbot available 24/7 with zero human intervention, capable of delivering instantaneous (<15ms latency), verified university information while maintaining multi-turn conversational context and high-confidence fallback mechanisms.

2. Proposed Solution & Approach

The solution delivers an automated, production-ready AI conversational assistant powered by a hybrid Natural Language Processing (NLP) pipeline and a calibrated Multi-Layer Perceptron (MLP) Neural Network classifier. The system extracts user intent using sublinear TF-IDF vectorization across word n-grams (1–3) and character n-grams (3–5), ensuring robust handling of typos, abbreviations, and informal Hindi-English student syntax. An entity extraction module automatically disambiguates department names (e.g., CSE, IT, ECE, ME) to dynamically route queries to specific Heads of Department (HODs). Multi-turn context is managed through an active state cache, and every interaction is persistently audited in a lightweight SQLite database for administrative analytics. The user interfaces include a responsive dual-theme FastAPI web portal with voice Speech-to-Text/Text-to-Speech and an interactive Streamlit analytics dashboard.

7. Challenges Encountered & Resolutions
Challenge 1: TensorFlow 2.18 / Python 3.12 Distutils & Protobuf Runtime Incompatibility
Impact: The original TensorFlow pipeline failed during compilation due to deprecated distutils in Python 3.12 and breaking C-extension descriptor changes in Google Protobuf 7.x.
Resolution: Re-architected the AI engine using Scikit-Learn's pure Python/Cython MLPClassifier with a 2-tier hidden layer topology (64 & 32 neurons) and Adam optimizer. This delivered 99.51% classification accuracy with zero C-runtime dependency conflicts and slashed memory footprint from 450MB to just 42MB.
Challenge 2: Out-Of-Vocabulary (OOV) Variations & Student Slang
Impact: Students frequently type informal queries, phonetic spelling variations (e.g., "hostel fee kitni h", "hod cse contact"), and abbreviations.
Resolution: Implemented sublinear TF-IDF vectorization combining word n-grams (1-3) with character n-grams (3-5), coupled with a calibrated confidence threshold (0.40). Queries below 40% probability trigger a helpful fallback prompt directing the student to specific university helpdesk email channels.
Challenge 3: Multi-Department Entity Ambiguity
Impact: General questions like "Who is the HOD?" lack department context, whereas specific queries like "Who is the HOD of CSE?" require tailored contact info.
Resolution: Engineered a contextual entity extraction module using regex keyword matching and stateful context variables (GreetingUserRequest, HODContext) to retain active conversation state.

B. Top 5 Evaluator Questions & Clear Answers (Easy to Remember)
Q1. Why did you choose TF-IDF + Neural MLP instead of just simple keyword matching?
Answer: "Keyword matching breaks if a student uses synonyms, spelling mistakes, or different grammar. TF-IDF gives higher weight to informative keywords, and the Neural MLP learns underlying semantic patterns across 412 query variations, giving 99.51% classification accuracy."
Q2. How do you handle queries where the student asks something completely outside the syllabus?
Answer: "Our model calculates a softmax probability score. If the maximum confidence score falls below 0.40 (40%), the bot triggers a safe fallback message advising the user to contact the official college helpdesk, preventing hallucinated or wrong answers."
Q3. Why did you switch from TensorFlow to Scikit-Learn MLPClassifier?
Answer: "In Python 3.12, legacy TensorFlow encountered distutils and protobuf incompatibilities. Scikit-Learn's MLPClassifier delivers identical deep-learning classification capability, runs 10x faster on CPU (11ms latency), and needs only 42MB of RAM, making it production-ready."
Q4. How does the multi-turn context work (e.g., asking for CSE HOD)?
Answer: "We use an entity extractor and session state cache. When a student asks general HOD info, the bot sets an active context tag. When the student replies 'CSE', the entity disambiguator pairs it with the previous context to return the exact CSE department HOD contact."
Q5. Is the user's data secure?
Answer: "Yes. No sensitive student PII or passwords are ever captured. Only sanitized queries, response tags, and latency timestamps are stored in SQLite for performance analytics, in strict accordance with the DPDP Act 2023."
